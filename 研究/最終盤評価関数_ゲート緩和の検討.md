# 最終盤評価関数 ゲート緩和の検討 — `G_A2` は緩められるか / 適用 turn を広げられるか

前提ドキュメント: `研究\最終盤評価関数_研究結果.md` / `_追加検証.md` / `_turn58以下の証明.md` / `_turn57以下の証明.md`

検証コード: `研究\verify\gate_ga_search.cpp`(本ドキュメントで新規作成)
—— 既存の `gate_direct_search.cpp` は形状段階で「空きマス 3 個のライン」を弾いてしまい
(`G_A2` の幾何条件)、**`G_A` だけを満たす局面を 1 つも生成できない**。
本プログラムはその制限を外し、制約(C) だけを課した局面を直接構成する。

---

## 0. 結論

**(1) `G_A2` を `G_A` に緩めることはできない。反例を構成した。**

> `G_A ∧ G_T ∧ G_3` を通過し、しかも到達可能なのに R2 が **勝敗を取り違える**局面が turn 57 に存在する。
> turn 57 の直接構成 50 万局面では、`G_A ∧ G_T ∧ G_3` 通過 27,488 件中 **誤断定 8 件・取りこぼし 10 件**。
> 反例狙いの形状(一直線 4 柱を高さ 1/2/2/3 に固定)に絞ると **通過 6 万件中 誤断定 7,186 件(12.0%)**。

破れる仕組みは 1 つに特定できた。`G_A` は「1石 + 空き3」のラインを許すので、
**段3 の水平ライン(H3)に黒石 1 個 + 空き 3 個**という配置が生き残る。黒はここに **2 手**で
リーチを作れてしまい、しかもそのリーチは **K の段3 = 埋没した奇数段** に生じるので黒の有効脅威になる。
2 手を稼ぐ燃料は「段4 の黒リーチ(段パリティ上は無効)の直下を打つテンポ手」である。
これは前ドキュメント §4.2 で特定した「無効脅威をテンポの燃料にする」機構そのものであり、
`G_A2` はこの入口(1石+空き3)を塞ぐことでそれを防いでいた。

**(2) turn の範囲を広げるなら、`G_A2` を捨てて `G_bd` を足すのが最も有望である。**

> **`G_bd`** := 「**既存の埋没リーチマスの直下マス `b_d` に触れる『生きたライン』(相手の石を 1 個も含まず、
> 空きマスが 2 個以上あるライン)が 1 本も存在しない**」

`G_A ∧ G_T ∧ G_bd` は、直接構成サーチの範囲で **誤断定が 1 件も出ない**(= 健全)。
しかも通過率は証明済ゲート `G_A2 ∧ G_T ∧ G_3` の **10〜80 倍**である。

| turn(試行数) | `G_A2 ∧ G_T ∧ G_3`(証明済・厳密) | `G_A ∧ G_T ∧ G_bd`(実測・健全) |
|---|---|---|
| 57(50 万) | 5,799 件(1.16%)/ 誤り 0 | **6,751 件(1.35%)/ 取りこぼし 1・誤断定 0** |
| 55(50 万) | 297 件(0.06%)/ 誤り 0 | **2,731 件(0.55%)/ 取りこぼし 3・誤断定 0** |
| 53(6 万) | 2 件(0.003%)/ 誤り 0 | **158 件(0.26%)/ 取りこぼし 4・誤断定 0** |
| 51(6 万) | 1 件(0.002%)/ 誤り 0 | **80 件(0.13%)/ 取りこぼし 1・誤断定 0** |

したがって **用途を「厳密な値として使う」から「勝敗を断定したときだけ枝を刈る」に変えれば、
適用 turn を大きく広げられる**見込みがある(追加検証 §7-(b) の使い方)。ただし**未証明**である。
§4 に、証明の骨格になる補題 3 本(補題 T1〜T3)を示す。

**(3) 構造の側は turn を大きく広げられる —— 平坦盤定理。**

> **定理 F(平坦盤定理)**: **段2 がすべて埋まっている**(= すべての柱の高さ ≤ 2 = **`G_T0`**)とき、
> 抽象モデル(創出なし)では
> **黒は絶対に勝てず、白は「段4 の埋没リーチ」を 1 個でも持てば必ず勝つ。**
> turn にも空きマス数にも柱の本数にも依存しない。

`G_T0` は `E ≤ 32`(turn ≥ 33)まで成立しうる条件で、実測通過率も **33%** と高い(§3)。
証明も 1 ページで済む(`_turn57以下の証明.md` §3.1 の「K 不在の場合」がそのまま定理 F である)。
**残る困難はすべて「創出」に集約されている** —— `G_T0` だけでは turn 57 で誤断定 5.3% が残る。

## 1. 追加したゲートの定義

`gate_ga_search.cpp` で新たに導入・測定した条件は次の 4 つである。

| 記号 | 定義 | 判定コスト |
|---|---|---|
| **`G_T0`** | 高い柱(h ≥ 3)が **0 本** ⟺ 段2 のマスがすべて埋まっている | `(~occ & mask_2) == 0` の 1 命令 |
| **`G_low`** | 段2・段3 の**埋没**空きマスに触れる生きたライン(空き 2 個以上)が無い | 対象マスは高々 2 個。その 7 本前後のラインを見るだけ |
| **`G_bd`** | **埋没リーチマスの直下マス `b_d`** に触れる生きたライン(空き 2 個以上)が無い | 同上。`b_d` は `(reach & ~hand) >> 16` |
| **`G_C`** | 「2石 + 空き2」のうち即置可能マスにリーチを作れるものが無い(追加検証 §2.2 の再掲) | `cnt[]` 走査 |

「生きたライン」= 相手の石を 1 個も含まないライン。空きマス 1 個以下のものは既存リーチか決着済なので除く。

```cpp
// b_d = 埋没リーチマスの真下。そこに触れる「単色 + 空き2 個以上」のラインが無いこと
static bool gate_bd(const Board &b)
{
    const ull occ = b.Me | b.You, emp = ~occ, hand = (occ << 16 | mask_1) & ~occ;
    const ull rB = Board::reach(b.Me) & ~b.You & emp, rW = Board::reach(b.You) & ~b.Me & emp;
    const ull cells = (((rB | rW) & ~hand) >> 16) & emp;      // 埋没リーチの直下マス
    if (!cells) return true;
    for (int i = 0; i < LINES_NUM; i++)
    {
        if (!(LINES[i] & cells)) continue;
        const int cm = popcount(b.Me & LINES[i]), cy = popcount(b.You & LINES[i]);
        if (cm && cy) continue;                                // 両色を含む = 死んだライン
        if (popcount(LINES[i] & emp) <= 1) continue;           // 既存リーチ / 決着済
        return false;
    }
    return true;
}
```

## 2. `G_A2` → `G_A` は不可能 — 反例

### 2.1 反例(turn 57・黒番・到達可能)

```
    z=1  z=2  z=3  z=4
y=4 OOXX OOXO OOXX XXOX
y=3 XXOX XXOO OXOO XOXO
y=2 XXOO -OXX ---X ----
y=1 OOXO XXOO OOOX XXOX
  x=1234 1234 1234 1234
     (X = 黒, O = 白, - = 空き)

turn = 57(黒番)   G_A = 1   G_A2 = 0   G_T = 1   G_3 = 1   G_bd = 0
空きマス:
  (x1,y2,段2)[即置可]  (x1,y2,段3)[白リーチ]  (x2,y2,段3)[即置可]  (x3,y2,段3)[即置可]
  (x1,y2,段4)[黒リーチ] (x2,y2,段4)[黒リーチ]  (x3,y2,段4)          (x4,y2,段4)[即置可]

R2 = 0(引き分け)     厳密解 = +1(黒の勝ち)  ← 取りこぼし
到達可能(交互着手 + 重力): YES
最善手順: 黒(x2,y2,段3) 白(x2,y2,段4) 黒(x3,y2,段3) 白(x1,y2,段2) 黒(x1,y2,段3)*勝ち
```

柱の高さは (x1,y2) = 3(= K)、(x2,y2) = 2、(x3,y2) = 2、(x4,y2) = 1。

- **R2 の言い分**: 盤上のリーチは「白の段3」1 個と「黒の段4」2 個。
  段3 は `owner(3) = 黒` なので白の段3 は**無効**、段4 は `owner(4) = 白` なので黒の段4 も**無効**。
  有効脅威が 1 つも無いので `m* = ∞` → 引き分け。
- **実際に起きること**: y=2 の段3 の行 `(x1..x4, y2, 段3)` は **黒石 1 個(x4)+ 空き 3 個**。
  これは `G_A` は通るが `G_A2` は通らない配置である。黒はここに 2 手で 3 石を並べられる。

### 2.2 破れる仕組み(2 手 + テンポ)

1. 黒 `(x2,y2,段3)`。これは **黒自身の段4 リーチ `(x2,y2,段4)` の直下 = `b_d`** なので、
   打った瞬間に段4 のリーチが即置可能になる。**白は阻止に強制される。**
2. 白 `(x2,y2,段4)`(強制)。
3. 黒 `(x3,y2,段3)`。これで段3 の行に黒が x2・x3・x4 と 3 個並び、
   **`(x1,y2,段3)` に黒の新しいリーチ**が生じる。x1 の柱は高さ 3(段2 が空)なので**このリーチは埋没**。
4. 段3 は奇数段なので、段パリティ定理よりこれは **黒の有効脅威**である。
   白は `(x1,y2,段2)` を打たされ、黒が `(x1,y2,段3)` を取って勝つ。

**要点は 2 つ。**

- **`G_A` が許す「1石+空き3」ラインは、2 手あればリーチになる。**
  `G_A2` はまさにこれを禁じるための条件であり、飾りではない。
- **黒はテンポを自前で調達できた。** 段パリティ上は無価値な「段4 の黒リーチ」の直下を打つことで
  白の応手を 1 手強制し、その間に段3 のラインを 1 手ぶん育てた。
  これは `_turn58以下の証明.md` §4.2 で特定した機構と同型である。

> **補題 R1(なぜ `G_A2` が要るか)**: `G_T` の下で、**新しく生じるリーチの段が 3 以下になりうるのは、
> 「段3 の水平ライン H3」または「高い柱 K を通る斜めライン」に限られる**(`_turn58以下の証明.md` 補題D の拡張)。
> `G_A2` はこれらのラインの空きマス数を 2 以下(= 死んだラインか既存リーチ)に強制するので、
> 段3 以下の創出そのものを消す。`G_A` だけではこの入口が開いたままになる。

### 2.3 数値

`gate_ga_search.exe <turn> <試行> <seed> <mode> <strict>` / `mode 3` は反例狙いの形状固定。

## 3. 定理 F(平坦盤定理)— 構造の側は turn を大きく広げられる

### 3.1 主張と証明

> **定理 F**: すべての柱の高さが 2 以下(`G_T0`)である抽象モデルの局面では、
>
> - **黒は勝てない。**
> - **白は「段4 の埋没リーチ(= 高さ 2 の柱の段4 にある白のリーチ)」を 1 個でも持てば勝つ。**
> - 持たなければ引き分け。
>
> turn・空きマス数・柱の本数に依存しない。

**証明.** 高さ 1 の柱は段4 の 1 マス(制約(C) より無ラベル)= **自由マス**、
高さ 2 の柱は「段3(即置可・無ラベル)+ 段4(ラベル可)」の 2 連である。
段2 以下は全部埋まっているので、埋没マスは**段4 だけ**である。
高さ 2 の柱を段4 のラベルで分類する:

| 段4 のラベル | 呼び名 | 段3 のマスの性質 |
|---|---|---|
| 無し | 中立2連 | どちらにも安全(中立マス 2 個) |
| 白 | **W スタック** | 黒にとって毒(黒が打てば白が段4 を取って勝つ)。白は自分から潰せる |
| 黒 | **B スタック** | 白にとって毒。黒は自分から潰せる |
| 両方 | **BW スタック** | 双方にとって毒 |

中立マスの総数を N、W / B / BW スタックの本数を w / β / γ とすると `E = N + 2(w + β + γ)`。

- **自分のスタックを自分から潰す(burn)手**は「自分 1 手 + 相手の強制阻止 1 手」で消費されるので、
  **中立マスの残数を変えず、手番も自分に戻る**。すなわち burn は **パス**である。
- したがって中立マスは**厳密に交互に**消費される。手番側を M とすると、
  N 個を消費し終えた時点の手番は **N が偶数なら M、奇数なら相手**である。
- `E = N + (偶数)` なので `N ≡ E (mod 2)`。また `E = 65 - turn` より
  **turn が偶数(M = 白)なら E は奇数 → N は奇数 → 詰まるのは黒**、
  **turn が奇数(M = 黒)なら E は偶数 → N は偶数 → 詰まるのは M = 黒**。
  いずれの場合も **詰まるのは必ず黒**である。
- 中立マスが尽きた黒は、自分の B スタックを burn し続けることしかできず、
  それも尽きれば **W / BW スタックの段3(毒マス)を打つしかない** → 白の勝ち。
  W も BW も 1 本も無ければ、黒は B スタックを潰しきって盤面が埋まり、引き分け。
- 白は「自分の手番では必ず中立マスが 1 個以上残っている」ので、毒マスを打たされることはない。∎

> **系 F1**: `G_T0` の下では R2 は `rW & mask_4` の 1 判定に退化する。
> 段2・段3 の判定は空振りする(そもそも埋没マスが無い)。
> **黒の勝ちは原理的に存在しない。**

> **系 F2**: `G_T0` は `E ≤ 32`(turn ≥ 33)で成立しうる。
> 実測通過率(直接構成サーチ)は turn 57 / 55 / 53 / 51 のいずれでも **33% 前後**で、
> turn が下がってもほとんど落ちない。`G_A2` の 1.1% → 0.002% という急落とは対照的である。

### 3.2 それでも足りない理由 — 創出

定理 F は抽象モデル(創出なし)の定理である。実盤面では `G_T0` だけでは足りない。

| turn | `G_T0` 通過 | 一致 | 取りこぼし | **誤断定** |
|---|---|---|---|---|
| 57 | 167,330 (33.5%) | 126,905 | 31,520 | **8,905 (5.3%)** |
| 55 | 166,747 (33.4%) | 107,955 | 42,257 | **16,535 (9.9%)** |
| 53 | 20,266 (33.8%) | 10,889 | 6,260 | **3,117 (15.4%)** |
| 51 | 19,942 (33.2%) | 8,284 | 7,053 | **4,605 (23.1%)** |

**誤断定が出る = 定理 F が言う「黒は勝てない」が破れている**、ということである。
`G_T0` の下では段3 のマスはすべて即置可能なので、**黒が段3 に埋没リーチを持つことは原理的に不可能**である。
それでも黒が勝てるのは、次の 1 つの機構による。

> **補題 T1(平坦盤で黒が勝つ唯一の道)**: `G_T0` の下で黒が勝つには、
> **黒が「白の安全手を潰す位置」に即置可能なリーチを作り、白に `b_d` を打たせる**しかない。
> 具体的には、黒が **W スタック / B スタックの段3(= `b_d`)にリーチを作る**と、
> 白はそこを打たされ、自分の脅威を捨てるか黒の段4 を開くかを強いられる。

これはまさに 研究結果 §3.5 の「テンポ手」であり、`G_bd` が禁じている配置そのものである。
実際 `G_T0 ∧ G_bd` では誤断定が 8,905 → 1,197(turn 57)、16,535 → 1,838(turn 55)へ 1 桁落ちる。
`G_C`(即置マスへの 1 手創出も禁止)まで足すと **0** になる(turn 57 で 4,687 局面、turn 55 で 2,119 局面)。

読み取れること:

- **`G_A ∧ G_T ∧ G_bd` は turn 57・55・53・51 で誤断定 0**(合計 **9,720 局面**)。
  取りこぼしは残るので**厳密ではない**が、**健全**(勝敗を断定したときは必ず正しい)である可能性が高い。
- 通過率は証明済ゲートの **9 倍(turn 55)〜 80 倍(turn 53)**。
  turn 53 では証明済ゲートが 6 万局面中わずか 2 件しか通らないのに対し、こちらは 158 件通る。
- **`G_low` は健全ではない**(turn 57 の 50 万試行で誤断定 2 件)。
  「段3 以下に創出させない」だけでは不十分で、**`b_d` を守るほうが本質的**であることを示している。
- `G_T0 ∧ G_bd ∧ G_C` も誤断定 0 だが、通過率で `G_A ∧ G_T ∧ G_bd` に劣り、取りこぼしも多い。
- `G_3` は `G_A ∧ G_T ∧ G_bd` の中では**冗長**だった(全標本で、`G_3` を足しても `G_C` を足しても
  通過数が 1 件も減らない)。`G_bd` が先に H3 全空きラインを弾いているらしいが、
  **これは実測の観察にすぎず、含意 `G_A ∧ G_T ∧ G_bd ⟹ G_3` を証明したわけではない。**
  実装では念のため `G_3` も併記しておくのが安全である。

### 4.2 証明の骨格(未完成)

`G_A ∧ G_T ∧ G_bd` の健全性を証明するには、次の 3 つの補題を詰めればよいと考えている。

> **補題 T2(テンポの中立交換)**: `G_bd` の下では、**創出によって生じる即置可能なリーチは必ず「中立マス」に生じる**。
> したがってその創出手と、強制される阻止手は、**中立マスを双方が 1 個ずつ消費する普通の交換**にすぎず、
> 抽象モデルの値を変えない(`_turn57以下の証明.md` 系 C3 の一般化)。

**根拠.** 即置可能マス u にリーチが生じたとする。u が `b_d` なら、u を含む生きたラインが要るので `G_bd` に反する。
よって u は `b_d` でない。即置可能かつ `b_d` でないマスは、打っても上に脅威を開かないので**中立マス**である。
創出手のほうも同様である。創出手は生きたライン上の即置可能マスだが、`G_bd` よりそのマスは `b_d` ではありえない
(`b_d` に触れる生きたラインが無いから)。よって創出手も中立マスである。∎

> **補題 T3(`b_d` は石を置く価値が無い)**: `G_bd` の下では、**`b_d` マスに打っても、
> どの生きたラインの石数も増えない**(`b_d` に触れる生きたラインが存在しないから)。
> すなわち **`b_d` を打つテンポ手は、創出の役には一切立たない。**

補題 T3 が §2.2 の反例を直接封じている。反例では黒が `(x2,y2,段3)` を打ったが、
このマスは「自分の段4 リーチの `b_d`」であると同時に「段3 の H3 ライン上の 2 石目」でもあった。
`G_bd` はこの**兼務**を禁止する。

> **注意(補題 T2・T3 の穴)**: `G_bd` はゲート判定時点の埋没リーチについての条件である。
> 対局が進んで**新しい埋没リーチが生じれば、新しい `b_d` マスが生まれる**。
> 補題 T2・T3 をそこまで拡張するには「新しい埋没リーチは段4 にしか生じない(→ 新しい `b_d` は段3)」
> ことと、「段3 のマスに触れる生きたラインが `G_bd ∧ G_A` の下で残っていない」ことを示す必要がある。
> **ここが現時点で最大の未証明箇所である。**

> **補題 T4(創出の競争)**: `G_A` の下で、リーチを作るには 1 本のラインに 2 手以上が要る。
> 補題 T2・T3 より攻撃側は「相手の応手を強制しながら同じラインを育てる」ことができないので、
> 相手には毎回自由な手番が入る。相手はその手番で当該ラインの即置可能な空きマスを取って**消火**できる。
> —— ここで「**消火に使える即置可能マスが必ず存在するか**」が未証明の穴である。

`_turn57以下の証明.md` の 補題 B は `G_A2 ∧ G_3` から「H4 ラインは即置可能マスを 2 個以上持つ」を導いていた。
`G_A` に緩めた場合の対応物、すなわち

> **予想 B′**: `G_A ∧ G_T ∧ G_bd` の下で、創出に使える生きたライン L はいずれも
> 「攻撃側が石を置く必要のあるマス」のうち 2 個以上が即置可能である。

を示せれば、`_turn57以下の証明.md` の 定理 C1 の議論(消火戦略 F + 補題 S)がそのまま移植でき、
**健全性どころか厳密性まで**言える。実測で取りこぼしが残っていることから、
予想 B′ は**そのままでは成り立たない**(= 厳密性は成り立たない)が、
「攻撃側が作れるのは段4 の脅威だけ」という弱い形なら成り立つ可能性がある。これが健全性の証明になる。

## 5. 実装への影響と推奨

### 5.1 現時点の推奨は変わらない

- **厳密値としての運用**: 証明済の範囲(`turn ≥ 61` は `G_A`、`turn 60・59` は `G_A2`(+`G_T`)、
  `turn ≤ 58` は `G_A2 ∧ G_T ∧ G_3`)を守る。効果が出るのは通過率 36〜53% の **turn 61〜62** だけである。
- **`G_A2` を `G_A` に置き換えてはいけない**(§2 の反例)。誤断定は探索の値を壊す。

### 5.2 turn を広げたい場合の設計案(未証明ゆえ既定オフ)

「勝敗を断定したときだけ枝を刈る」用途なら、`G_A ∧ G_T ∧ G_bd` が候補になる。

```cpp
// 未証明。実測では turn 57・55・53・51 で誤断定 0(9,720 局面)。既定は無効にしておくこと。
if (turn <= 58 && endgame_gate_A(b.cnt) && tall_columns_le1(b) && endgame_gate_bd(b))
{
    const int v = endgame_R2(b, rMe_raw, rYou_raw, turn);
    if (v != 0) return v;          // 断定したときだけ信じる(引き分け判定は無視)
}
```

コストは `G_bd` の追加分だけである。`b_d` マスは
`((reach & ~hand) >> SIZE*SIZE) & empty` で 1 命令ずつ、対象マスは通常 0〜2 個しかないので、
そこに触れるラインだけ `cnt[]` を引けばよい。`reach()` は葉で既に計算しているので追加の再計算は不要。

### 5.3 定理 F の使い道

`G_T0` は `(~occ & mask_2) == 0` の **1 命令**で判定でき、通過率は turn が下がっても 33% 前後を保つ。
定理 F より、この条件の下では

- **「黒の勝ち」を返す評価は原理的に誤り**(抽象モデルでは黒は勝てない)
- R2 は `rW & mask_4` の 1 判定に退化する

ので、少なくとも **評価関数のヒューリスティックとしての形を単純化・高速化**できる。
厳密な打ち切りに使うには §4 の創出条件が要る。

### 次にやるべきこと

1. **予想 B′ の検証**(§4.2)。`G_A ∧ G_T ∧ G_bd` の下で「創出に使えるラインは即置可能マスを 2 個以上持つ」か、
   持たない反例があるかを直接構成で調べる。持たない反例の形が分かれば、それを弾く条件が `G_bd` の次の一手になる。
2. **健全性のより大きな標本での確認**。現状 9,720 局面では「誤断定 0」の根拠としてまだ薄い。

   (`G_T0 ∧ G_bd`)ので、`G_A` 相当の条件がどうしても要るのかを見極める必要がある。
