## 0. 結論(要約)

| 手数 | 空き E | 手番 | 厳密な簡略評価関数 | 性質 |
|---|---|---|---|---|
| 64 | 1 | 白 | **常に 0(引き分け)** | 厳密。リーチ判定すら不要 |
| 63 | 2 | 黒 | 白が段4にリーチ → 白勝ち、それ以外 0 | 厳密。先手は絶対に勝てない |
| 62 | 3 | 白 | 段パリティ規則 R2 | **健全**(誤断定ゼロ)だが不完全(5.5% を引き分けと誤判定) |
| 61 | 4 | 黒 | 段パリティ規則 R2 | 2.0% で誤断定。ただし「脅威創出不可能」局面では厳密 |
| 60 | 5 | 白 | 段パリティ規則 R2 | 1.8% で誤断定。「脅威創出不可能」局面では健全(誤断定ゼロ) |

中核となる発見は次の **段パリティ定理** である。

> **制約(C)の下で、すぐに置けないマス(埋没リーチ)にあるリーチは、**
> **そのマスの段が奇数(段1・段3)なら黒の勝ち、偶数(段2・段4)なら白の勝ちを意味する。**
> **この条件に手数 `turn` も空きマス数 `E` も現れない。**

現行実装 `code\evaluate_alpha_t.hpp` の `turn >= 60` 分岐が「黒は `mask_3`、白は `mask_4`」という
一見不可解な定数を使っているのは、まさにこの定理の帰結であり、**着想は正しい**。
ただし後述する **2 つの欠陥** があり、白番の局面で誤った勝敗を返す。

## 1. 前提と記法

### 1.1 手数・空きマス

- `turn` = これから着手する手の番号(`Board::turn() = popcount(Me|You) + 1`)。1〜64。
- `turn` が奇数なら黒(先手)、偶数なら白(後手)の手番。
- 空きマス数 `E = 65 - turn`。turn=64 → E=1、turn=60 → E=5。
- 段(層)は 1〜4 で表記する。コード上の `mask_1..mask_4` = z=0..3 に対応。

### 1.2 評価関数が呼ばれる条件 = 制約(C)

`ai_player_pvs_inc_id.hpp:99-119` より、`evaluate_func` が呼ばれるのは次を **両方**満たすノードだけである。

```cpp
const unsigned long long r = hand & rMe_raw;
if (r) return INF - board.b.turn();          // 手番側に即勝ち手 → 評価関数を通らない
...
if (hand & rYou_raw) hand = hand & rYou_raw; // 相手に即リーチ → 阻止手に強制、評価関数を通らない
else if (level <= 0) { ... evaluate_func ... }
```

> **制約(C)**: 評価関数が見る局面では、**即座に置けるマス(`hand`)の上には、どちらの色のリーチも存在しない。**

これは研究計画の制約そのものである。以下の解析はすべて (C) を仮定する。
(C) を満たさない局面に以下の式を適用すると誤るので、評価関数の外で使ってはならない。

### 1.3 柱(スタック)と段の関係

重力があるので、ある柱の空きマスは必ず**上から連続した h 個**である。したがって:

- **補題 1**: 段 m のマスが空なら、その柱の段 m+1..4 も空である。
  すなわち **同じ柱でそのマスより上にある空きマスはちょうど `4 - m` 個**(m にのみ依存)。
- **補題 2**: 空きマス h 個の柱の最下段(=即座に置けるマス)は段 `5 - h`。
  - h=1 → 段4、h=2 → 段3、h=3 → 段2、h=4 → 段1。
- **系**: 段1 が空ならその柱は 4 マスすべて空であり、段1 は必ず即置可能。
  よって **制約(C) の下で「段1 の埋没リーチ」は存在し得ない。**

空きマスの形状は E の分割(柱の高さの多重集合)で表す。例: E=3 なら `1+1+1` / `2+1` / `3`。

### 1.4 リーチの基本性質

`reach(B)` は「B が 3 個並び、4 個目が空」であるマスを返す(呼び出し側で `& ~相手石` される)。

- **補題 3(リーチ不滅性)**: X のリーチマス c の属するラインは「X の石 3 個 + c」で構成される。
  よって **c 以外のどのマスに誰が着手しても、そのリーチは消えない。** c 自身が埋まったときだけ、
  X が置けば勝ち、相手が置けば阻止となる。
- **補題 4(リーチ創出)**: 手を打って新しく生じるリーチは **打った本人の色だけ**である。
  X が p に打って c に X のリーチが生じるのは、p と c を含むライン L の残り 2 マスが
  ともに X の石であるとき、すなわち **L に X の石がちょうど 2 個・空きがちょうど 2 個**のときに限る。

## 2. 手数ごとの厳密解析

### 2.1 64手目(E=1、白番)

空きマスは 1 個。補題 1 よりその上に空きは無いので、**そのマスは必ず段4**であり、即座に置ける。

- 黒はもう着手できない。よって **黒が勝つことはない。**
- 白はそのマスに置く。勝つのは「そのマスが白のリーチである」場合のみ。
- しかし制約(C) より即置可能なマスに白のリーチは無い。

> **64手目の評価関数: 常に `0`(引き分け)。リーチの計算すら不要。**

研究計画の「白のリーチがあれば INF、無ければ 0」は一般論としては正しいが、
探索側が即勝ちを先に処理しているため、**評価関数に到達する 64 手目は必ず引き分けである。**

*検証: 51,295 局面すべてが引き分け(勝ち 0 / 負け 0)。*

### 2.2 63手目(E=2、黒番)

形状は `1+1`(2 本の柱の段4)か `2`(1 本の柱の段3・段4)。

**形状 `1+1`**: 2 マスとも即置可能なので (C) よりどちらの色のリーチも無い。
黒が一方に、白が他方に置いて終局。補題 4 より黒の着手が白のリーチを作ることはない。→ **引き分け**。

**形状 `2`**: 下から P(段3、即置可)、Q(段4)。黒は P しか打てない。次に白が Q を打つ。
- 黒は P に打つが、(C) より P は黒のリーチではないので勝てない。
- 白が Q で勝つ ⟺ **Q が元から白のリーチ**。
  (補題 3 より黒の P への着手では消えず、補題 4 より新たに作られることもない。)

> **63手目の評価関数(手番=黒): 白が段4にリーチを持てば `-INF`、それ以外は `0`。**
> **先手が勝つ手順は存在しない。**

形状 `1+1` では段4の 2 マスとも即置可能なので (C) によりリーチが無く、
`rYou & 段4` という 1 つの式で両形状を同時に正しく扱える。

*検証: 72,898 局面。手番(黒)の勝ち 0 件、負け 19,856 件、引き分け 53,042 件。式は 100% 一致。*

### 2.3 62手目(E=3、白番)

形状は `1+1+1` / `2+1` / `3`。白は 62・64 手目の 2 手、黒は 63 手目の 1 手を持つ。

**形状 `3`**(P1:段2 即置可、P2:段3、P3:段4): 手順は完全に強制。白 P1 → 黒 P2 → 白 P3。
- 黒が P2 のリーチを持てば **黒の勝ち**(63手目)。白の P1 着手では消せない(補題 3)。
- そうでなく白が P3 のリーチを持てば **白の勝ち**。
  P1 と P3 を含むラインは垂直線だけで、間の P2 が空なので白の P1 着手で P3 のリーチが新たに生じることはない。
- 黒の P2 と白の P3 が同時に存在する場合は **段が低い黒(段3)が先に発火**して黒の勝ち。

**形状 `2+1`**(柱X: P 段3 即置可 / Q 段4、柱Y: R 段4 即置可): 白は R を打つ「安全な手」を持つため、
白 R → 黒 P(強制)→ 白 Q の順になり、**黒が勝つ手順は存在しない**。
- Q が白のリーチなら **白の勝ち**。
- Q が黒のリーチでも、上の手順で白が Q を塞ぐので黒は勝てない。

**形状 `1+1+1`**: 3 マスとも即置可能なので (C) よりリーチは無い。黒が勝つことはない(補題 4)。
白は「打った手が残り 2 マス両方に白のリーチを作る」場合のみ勝てる(二重脅威)。

> **62手目**: 既存リーチだけを見る式は **健全**(勝敗を誤って断定しない)が **不完全**。
> 取りこぼすのは「白が打って新しいリーチを作る」ケースだけである(形状 `1+1+1` の二重脅威、
> 形状 `2+1` で白の R 着手が Q に白リーチを作るケース)。

*検証: 88,467 局面。R2 は誤断定 0 件、引き分けと誤った取りこぼし 4,897 件(5.5%)。*
*1 手読みを足すと 88,467 件すべて厳密に一致 → 取りこぼしの原因が「創出」だけであることの裏付け。*

### 2.4 61手目以降

E=4 以降は双方が 2 手以上持ち、形状も 5 通り以上になるため個別列挙は現実的でない。
そこで一般定理に移る。

## 3. 段パリティ定理

### 3.1 定理

> **定理**: 制約(C) の下で、盤上のリーチが色 X のマス c(段 m)ただ 1 つであり、
> 以後どちらも新しいリーチを作れないとする。このとき
>
> - X = 黒 かつ m が奇数、または X = 白 かつ m が偶数 → **X の勝ち**
> - それ以外 → **引き分け**
>
> **手数 `turn` にも空きマス数 `E` にも依存しない。**

### 3.2 証明

c の直下の空きマスを `b_d`、c より下の同じ柱の空きマス数を `d`(制約(C)より `d ≥ 1`)、
**他の柱**の空きマス総数を `F` とする。補題 1 より c より上の空きは `4 - m` 個なので

```
E = d + 1 + (4 - m) + F
```

**(a) 双方とも `b_d` を打ちたくない。**
X が `b_d` を打てば次に相手が c を塞いでリーチが死ぬ。相手が `b_d` を打てば次に X が c で勝つ。
よって双方 `b_d` を避ける。

**(b) 安全手の総数**は「他の柱の F マス」+「`b_1..b_{d-1}`」= `S = F + d - 1` 個。
c より上のマスは c が埋まるまで打てないので、この勘定に入らない。

**(c) ツークツワンク**。双方が安全手を消費し合い、尽きた時点の手番側が `b_d` を打たされ、
その次の手番が c を取る。手番 M から S 手後の手番は、S が偶数なら M、奇数なら相手 O。したがって

- S が偶数 → `b_d` を打つのは M、**c を取るのは O**
- S が奇数 → `b_d` を打つのは O、**c を取るのは M**

**(d) S のパリティ**。上の E の式から

```
S = F + d - 1 = E - (4 - m) - 2 = E + m - 6 = (65 - turn) + m - 6 = 59 + m - turn
```

**(e) 場合分け**。
X = M(手番側がリーチ保有)のとき、X が勝つ ⟺ S が奇数 ⟺ `m ≡ turn (mod 2)`。
`turn` が奇数のとき M は黒なので「黒 かつ m 奇数」、偶数のとき M は白なので「白 かつ m 偶数」。
X = O(相手側がリーチ保有)のとき、X が勝つ ⟺ S が偶数 ⟺ `m ≢ turn (mod 2)`。
`turn` が奇数のとき O は白で m は偶数、偶数のとき O は黒で m は奇数。**いずれも同じ条件に帰着する。** ∎

### 3.3 系

- **系 1**: 判定条件は「リーチの色」と「段」だけで決まり、手番にも手数にも依存しない。
- **系 2**: §1.3 の系より段1 の埋没リーチは存在しないので、実効的には
  **黒は段3、白は段2 と段4** の 3 パターンだけを見ればよい。
- **系 3**: 白の段2 リーチが成立するのは「4 マスすべて空の柱」があるとき、すなわち `E ≥ 4`(turn ≤ 61)。
  白の段4・黒の段3 は `E ≥ 2` / `E ≥ 3` から現れる。

### 3.4 複数リーチがある場合 — 低段優先

有効な脅威(黒の奇数段リーチ / 白の偶数段リーチ)が複数あるときは、
**段が最も低い脅威の保有者が勝つ**。

- 同じ柱の中なら下から順に埋まるので自明。
  例: 柱が 4 マス空で白が段2、黒が段3 にリーチ → 黒が段1 を打った直後に白が段2 で勝つ。
- 異なる柱の場合も、検証範囲(turn ≥ 61 かつ脅威創出不可能)では反例が見つからなかった。
  turn=60 では 12,793 件の競合のうち 12,535 件(97.98%)で低段優先が的中した(残りは §3.5 の創出が原因)。

なお現行実装の「エスケープフィルタ」
```cpp
rMe &= ~(rYou << SIZE * SIZE);   // 相手リーチの真上にある自分のリーチを消す
```
は、段 m と段 m-1 が逆パリティであることから **低段優先と同じ結論を与える**(定理と矛盾しない)。
実際、黒番の局面では現行実装と低段優先版は完全に一致した。

### 3.5 定理が破れる条件 — テンポ手(脅威創出)

定理の仮定「新しいリーチを作れない」が崩れると、**安全手の勘定が狂ってパリティが反転する**。
特に致命的なのが次のパターンである。

> **即座に置けるマスに新しいリーチを作る手** は、相手に阻止を強制する **テンポ手**になる。
> 相手は安全手を 1 つ余計に消費させられ、ツークツワンクの手番が入れ替わる。

**実例(turn=61、黒番、厳密解=引き分け、R2 の予測=白勝ち):**

```
    z=1  z=2  z=3  z=4
y=4 XOOO OOOX XXXO OOOX
y=3 OXOO OOXX -OXX -XOX
y=2 XXOX XOXX XXOX OOXO
y=1 OXXO XXXO -OXX -OOO
  x=1234 1234 1234 1234
空き: (x1,y1,段3)[即置可] (x1,y3,段3)[即置可] (x1,y1,段4)[白リーチ] (x1,y3,段4)
```

白は (x1,y1,段4) に段4(偶数段)のリーチを持つので、定理どおりなら白の勝ちのはずである
(安全手 S = F + d - 1 = 2 + 1 - 1 = 2、偶数 → 黒が (x1,y1,段3) を打たされる)。
ところが x=1・z=段3 の y 方向のラインは `空 / 黒 / 空 / 黒` であり、
**黒が (x1,y3,段3) に打つと即置可能な (x1,y1,段3) に黒リーチが生じる。**
白はこれを塞がざるを得ず、その結果 (x1,y1,段4) は黒が取って引き分けになる。

```
最善手順: 黒(x1,y3,段3) 白(x1,y1,段3)[阻止強制] 黒(x1,y1,段4)[白の脅威を塞ぐ] 白(x1,y3,段4) → 引き分け
```

**創出の可否は補題 4 より「ある色の石がちょうど 2 個・空きがちょうど 2 個のライン」の有無で判定できる。**
これは `BoardInc::cnt[]` から既存の `flag_tbl` が計算している `v == ±2` と同一条件であり、
実装コストはほぼゼロである。

この条件で局面を絞ると、段パリティ規則の精度は劇的に上がる(§5 の表を参照):

| turn | 創出不可能な局面の割合 | その部分集合での R2 |
|---|---|---|
| 62 | 53.3% | **厳密(誤り 0 / 取りこぼし 0)** |
| 61 | 36.0% | **厳密(誤り 0 / 取りこぼし 0)** |
| 60 | 21.0% | 健全(誤り 0)、取りこぼし 70 / 28,462 = 0.25% |
| 59 | 12.3% | 誤り 531 / 20,705 = 2.6% |

## 4. 提案する簡略評価関数 R2

```cpp
// 前提: 制約(C)(即置可能マスに双方リーチ無し)が成立していること
// rB, rW は空きマス上の黒 / 白のリーチ集合
// 段が低い有効脅威から順に見る(低段優先)
static const unsigned long long MASK[5] = {0, mask_1, mask_2, mask_3, mask_4};
for (int m = 1; m <= 4; m++)
{
    if ((m & 1) && (rB & MASK[m])) return 黒の勝ち;   // 奇数段は黒(実際は m=3 のみ)
    if (!(m & 1) && (rW & MASK[m])) return 白の勝ち;  // 偶数段は白(m=2, 4)
}
return 0;
```

段1 は §1.3 の系より常に空振りするので、実際には

```cpp
if (rW & mask_2) return 白の勝ち;   // ← 現行実装の白番分岐に欠けている
if (rB & mask_3) return 黒の勝ち;
if (rW & mask_4) return 白の勝ち;
return 0;
```

の 3 段判定でよい。**手番による分岐は不要**(系 1)。符号だけ手番視点に変換すればよい。

### 適用範囲の指針

| 使い方 | 安全に使える手数 |
|---|---|
| 厳密な終端評価として使う(値をそのまま返す) | **turn ≥ 63** |
| 厳密な終端評価として使う + 脅威創出不可能を確認 | **turn ≥ 61** |
| 「勝ち/負けを断定したときだけ信じる」枝刈りに使う | **turn ≥ 62**(誤断定 0 を確認済み) |
| 上記 + 脅威創出不可能を確認 | **turn ≥ 60**(誤断定 0 を確認済み) |
| ヒューリスティック(現行と同じ扱い) | turn ≥ 60 でも現行より高精度 |

補足: R2 を葉に使う `d` 手読みは、**葉が turn 63 以降に落ちるなら厳密**である
(turn=60 から 3 手読み、turn=61 から 2 手読み、turn=62 から 1 手読みで、いずれも全件一致)。

## 5. 現行実装の検証結果

対象は `code\evaluate_alpha_t.hpp:55-67`(`reach_layer_intersection_t` の `turn >= 60` 分岐)。

```cpp
if(now == Color::Black)
{
    if(rMe & mask_3 || intersection_3) sum = INF - 100000;          // 黒の段3 → 黒勝ち
    else if(rYou & mask_2 || rYou & mask_4) sum = - INF + 100000;   // 白の段2/段4 → 白勝ち
}
else
{
    if(rMe & mask_4) sum = INF -100000;                             // 白の段4 → 白勝ち
    else if(rYou & mask_3 || intersection_3) sum = - INF + 100000;  // 黒の段3 → 黒勝ち
}
```

### 5.1 正しい点

- 「黒は `mask_3`、白は `mask_2`/`mask_4`」という段の割り当ては **段パリティ定理と完全に一致**する。
  段1 を見ていないのも正しい(存在し得ないため)。
- エスケープフィルタ `rMe &= ~(rYou << 16)` は同一柱内の低段優先と等価で、正しく機能している。
- **64手目・63手目では現行実装も厳密**(それぞれ 51,295 / 72,898 局面で全件一致)。
- 62手目でも誤断定は 0 件(健全)。

### 5.2 欠陥 A: 白番分岐に「白の段2」の判定が無い

黒番分岐には `rYou & mask_2` があるのに、白番分岐には `rMe & mask_2` が無い。
白が段2 に埋没リーチを持つ局面(4 マス空の柱が必要 = `E ≥ 4`)で **白の勝ちを見逃す**。

- turn=60 では 135,345 局面のうち **4,096 件(3.0%)** を引き分けと誤判定していた。

### 5.3 欠陥 B: 白番分岐の優先順位が逆

白番分岐は `rMe & mask_4`(白の段4)を `rYou & mask_3`(黒の段3)より **先に**判定する。
低段優先が正しいので、両方存在する局面では **勝者を取り違える**。

**実例(turn=60、白番、厳密解 = 黒の勝ち、現行実装 = 白の勝ち):**

```
    z=1  z=2  z=3  z=4
y=4 OXOO XOOO OXO- OXX-
y=3 XOXO OXXX OXOO XXOO
y=2 XOOX O-XO X-OX O-XX
y=1 XOXX XOXO XXXO OXOX
  x=1234 1234 1234 1234
空き: (x2,y2,段2)[即置可] (x2,y2,段3)[黒リーチ] (x4,y4,段3)[即置可]
      (x2,y2,段4)[黒リーチ] (x4,y4,段4)[白リーチ]
最善手順: 白(x2,y2,段2) 黒(x2,y2,段3) で黒の勝ち
```

白は段4 にリーチを持つが、より低い段3 に黒のリーチがあるため黒が先に発火する。
白が (x4,y4,段3) を打って自分の脅威を開いても、黒がそれを塞いだ後に白は
(x2,y2,段2) を打たされ、黒が段3 で勝つ。

- turn=60 では **3,121 件(2.3%)** で勝者を取り違えていた。

### 5.4 修正の効果(turn=60、135,345 局面)

| 版 | 一致 | 取りこぼし | **誤断定** |
|---|---|---|---|
| R0 現行 | 107,172 (79.2%) | 22,677 | **5,496 (4.1%)** |

欠陥はどちらも **白番分岐にのみ**存在する。

## 6. 数値検証の方法と結果

### 6.1 方法

`研究\verify\endgame_verify.cpp`。

1. **局面生成**: 空盤からランダムプレイアウト。ただし探索木の葉と同じ条件を再現する。
   - 手番側に即勝ち手がある局面が現れたらその試行を打ち切る(探索では評価関数に到達しないため)
   - 相手に即リーチがあれば阻止手に強制する
   - 制約(C) を満たす局面だけをサンプルとして記録する
2. **厳密解**: 残り空きマス数が少ないので終局まで全探索(勝ち +1 / 引き分け 0 / 負け -1、手番視点)。
3. **比較**: R0(現行)/ R0a / R1(黒優先)/ R2(低段優先)/ R2 を葉にした d 手読み、を厳密解と突き合わせる。

   - `bad`(誤断定) = 勝敗を取り違えた、または引き分けを決着と判定 → 危険な誤り

## 7. 現行コードへの適用案(未実装 / 指示待ち)

`code\evaluate_alpha_t.hpp` の `turn >= 60` 分岐を次のように置き換えるだけで、
turn=60 の誤断定を 4.1% → 1.8%、一致率を 79.2% → 84.5% に改善できる。手番分岐も不要になり短くなる。

```cpp
if(turn >= 60){
    // 段パリティ定理: 黒は奇数段(実効は段3)、白は偶数段(段2, 段4)。低い段が優先。
    // rMe/rYou はエスケープフィルタ適用後のもの。intersection_3 は段3 なので黒側に数える。
    const unsigned long long rB = (now == Color::Black) ? rMe : rYou;
    const unsigned long long rW = (now == Color::Black) ? rYou : rMe;
    int v = 0;
    if      (rW & mask_2)                  v = -1;   // 白の段2
    else if ((rB & mask_3) || intersection_3) v = +1; // 黒の段3
    else if (rW & mask_4)                  v = -1;   // 白の段4
    if (v) sum = (now == Color::Black ? v : -v) * (INF - 100000);
    return sum;
}
```

この置き換え案そのものを `endgame_verify.cpp` の `ruleR2impl()` として実装し、
全標本(turn 56〜64 の 1,392,179 局面)で `ruleR2()` と値が完全一致することを確認済みである
(不一致が 1 件でもあれば検証プログラムが即停止する)。

さらに踏み込む場合の選択肢:

- **(a) 適用開始手数を早める**: 「2 石 + 空き 2 のライン」が無いこと(= `flag_tbl` の `v==±2` が
  1 本も立たないこと)を条件に加えれば、turn ≥ 61 で厳密、turn ≥ 60 で健全になる。
  → **この案は `研究\最終盤評価関数_追加検証.md` で個別列挙・実測・コスト測定まで完了した。**
  結論は「`G_A`(2石+空き2 が無い)で turn ≥ 61 が厳密(証明可)、`G_A2`(1石+空き3 も無い)で turn 60・59 も厳密、
  判定コストは `BoardInc::cnt[]` を SSE2 で走査して +6.3 ns/回」。
- **(b) 健全性を使った枝刈り**: turn ≥ 62 では R2 が勝敗を断定したとき 100% 正しい(33,951 件で誤り 0)ので、
  断定時のみ即 return し、引き分け判定時だけ探索を続ける、という使い分けができる。

いずれも `研究\最終版研究計画.md` の docs-first 方針に従い、**本ドキュメントの段階では未実装**とする。

## 8. 今後の課題

> 課題 1 は続編 `研究\最終盤評価関数_追加検証.md` で構造定理として決着した。
> 「R2 が破れるのは**空きマス3個以上の柱が2本以上**あるときに限る」(抽象モデルの完全列挙 E ≤ 10 で確認)。
> turn ≥ 60 では原理的にそうならないため R2 が成立する。

1. **turn ≤ 59 の理論**: 段パリティ定理の「安全手の数え上げ」を、複数の脅威が互いの安全手を
   潰し合うケースまで拡張する必要がある(Connect Four の odd/even threat 理論の 3 次元版)。
   turn=59 では創出不可能な局面ですら誤断定が 2.6% 残っており、単純な低段優先では足りない。
   → 破れる条件は特定済み(上記)。これを式に取り込めれば `G_T` を外して適用範囲を広げられる。
2. **創出を式に取り込む**: 62 手目の取りこぼし 5.5% は「白が打って二重脅威を作る」ケースのみである。
   `makeT` 相当の既存機構で表現できる可能性が高い。
3. **速度効果の実測**: 本ドキュメントは正確性のみを扱った。実際の NPS / 探索時間への効果は
   `docs\実行結果` のベンチ手順で別途測定が必要。
4. **標本の偏り**: 局面はランダムプレイアウト(即勝ち回避・阻止強制つき)で生成しており、
   実戦の探索木に現れる分布とは完全には一致しない。網羅列挙による裏取りは未実施。
