## 1. R3 の run 拡張(課題 1)

### 1.1 柱をブロック列に分解する

柱 j(高さ h)を下から走査し、次を繰り返す。

```
[ゲート手前の中立マス nu 個] [ゲート 1 マス] [連続ラベル run r マス] → 次のブロックへ
```

各ブロックについて、補題 Q より**踏んだ側の色で結果が決まる**。
`A = owner(ゲートの段)`、`B = opp(A)` として:

| 踏む側 | 発火するもの | 結果 |
|---|---|---|
| **A** | run 中の最初の**有効脅威**(段 e) | `owner(e)` の勝ち。無ければ**素通り** |
| **B** | run 中の最初の**無効脅威**(段 f) | `opp(owner(f))` の勝ち。無ければ**素通り** |

**どちらの色が A になるかは 補題 P が自動的に決める**(段 m のマスで手番が `owner(m)` になるのは
柱の外の空きマス数が偶数のときだけ)ので、色ごとに結果は一意に定まる。

**単一ラベルの場合の確認**: 色 X の脅威が段 λ にあるとき
- 有効(X = owner(λ)):A = owner(λ−1) = opp(X) が踏む → X の勝ち。B = X が踏む → 素通り(= burn)。
- 無効(X = opp(owner(λ))):A = X が踏む → 素通り(= burn)。B = opp(X) が踏む → X の勝ち。

いずれも **「踏んで負けるのは opp(X)、素通りできるのは X」**で、補題 N1 に一致する ✓。

### 1.2 前回版が外していた 2 つの原因

前回の単一ラベル版 R3 を run にそのまま広げると E ≤ 9 で 404 件外した。原因は 2 つあった。

**原因 (a): 「踏むと踏んだ側が勝つ」ブロックの存在。**
単一ラベルでは `out ≠ 踏んだ側` が常に成り立つ(上の確認のとおり)。
ところが run があると **`out = 踏んだ側`** が起こる。例:`h=3, ℓ(段3)=白, ℓ(段4)=白`。
A = owner(段2) = 白 が踏むと、最初の有効脅威は段4 の白なので**白が勝つ**。
前回版は「詰まる側だけがブロックを踏む」と仮定していたので、
**手番側が今すぐ踏んで勝てる筋**を見落としていた。
→ 修正: 縮約ゲームを「詰まる側の burn 合戦」ではなく
**「手番 / 中立マスの残数 / 各柱のブロック番号」を状態とする通常のゲーム**にした。

**原因 (b): ゲート手前の中立マスには順序制約がある。**
中立マスを 1 つのプールとして交換可能に扱っていたが、
**柱 j のゲートを踏むには、その柱の「ゲート手前のマス」を先に埋めておく必要がある**(重力)。
上の例で白が段2 のゲートを踏むには、まず段1 を誰かが埋めねばならず、その 1 手の間に相手が動ける。
→ 修正: 中立マスを **「自由マス」**(ブロックを持たない柱のマス)と
**「ゲート手前のマス c_j」**(順序制約つき)に分けた。

修正後、E ≤ 9 で 404 → 0、E ≤ 11 で **250,755 パターン全一致**になった。

### 1.3 縮約ゲーム(R3 の最終形)

```
状態: 手番 mover / 自由マスの残数 Nfree / 各ブロック柱の (ブロック番号 bi_j, ゲート手前の残数 c_j)

手:
  ・自由マスを 1 個打つ            → Nfree--     、手番交代
  ・柱 j のゲート手前を 1 個打つ    → c_j--       、手番交代
  ・c_j == 0 の柱 j のゲートを踏む:
        out = (mover == owner(ゲートの段)) ? outA : outB
        out == mover      → mover の勝ち
        out == opp(mover) → mover の負け(選べはする)
        素通り            → 1+r マス消費。手番は r が奇数なら mover に戻り、偶数なら相手へ。
                            bi_j++、c_j ← そのブロックの上の中立マス数
  ・打つ手が無い(盤が埋まった)     → 引き分け
```

状態数はブロックを持つ柱の本数(E ≤ 11 なら高々 5 本)で決まり、実測で数千程度である。

### 1.4 意味

- **抽象モデルでは `G_T` が完全に不要になった。** ゲートから `tall_columns_le1()` を削れる。
  実測通過率は turn 57 で 84.7% → 100%、turn 50 で 40.1% → 100%(`_追加検証.md` §2.4)。
- 構造定理(`tall ≤ 1` なら R2 厳密)は R3 の系として再導出される。
  `tall ≤ 1` では「押し返せる段3 の脅威」が高々 1 個しか無いので、R3 が R2 に退化する。
- ただし **R3 が使えるのは「創出が起きない」ことが保証された局面に限る**という点は変わらない。
  そして §2 のとおり、その保証こそが崩れた。

## 2. 定理 C1 の反証(課題 3)

### 2.1 何を判定したか

`theoremC1_check.cpp` は、`G_A2 ∧ G_T ∧ G_3` を通過する局面それぞれについて次の**補助ゲーム**を解く。

- 攻撃側 A は「**根で 4 マスとも空だったライン** L に A の石を 3 個以上並べ、相手の石を 0 に保つ」ことを目指す。
- 守備側 D は自由に打てるが、**A が即置可能マスにリーチを持つときは阻止に強制される**
  (2 個以上あれば止められないので A の成功とみなす)。
- 盤が埋まるまで A が成功しなければ D の勝ち。

さらに 2 つのパラメータで厳しさを変えた。

- `strict`: 成功を「**残る空きマスが埋没している**」場合に限る(= 段パリティ上意味のある創出だけを数える)。
- `realistic`: **A も D の即リーチの阻止に強制される**(現実のゲームに近い)。

「全局面で D が防ぎきる」なら 定理 C1 の結論は正しい。

### 2.2 結果 — 定理 C1 の結論は偽

turn 57(E = 8)、40,000 試行、`G_A2 ∧ G_T ∧ G_3` 通過 **9,555 局面**。

| モデル | 黒が創出できなかった | 白が創出できなかった | **黒の成功率** | **白の成功率** |
|---|---|---|---|---|
| 緩い(3 石並べば成功 / A は自由) | 9,140 / 9,555 | 9,107 / 9,555 | **4.3%** | **4.7%** |
| strict(埋没リーチのみ / A は自由) | 9,141 / 9,555 | 9,107 / 9,555 | **4.3%** | **4.7%** |
| **strict + realistic(双方強制あり)** | 9,405 / 9,555 | 9,363 / 9,555 | **1.6%** | **2.0%** |

**どのモデルでも反例が出る。定理 C1 の結論そのものが偽である。**
しかも「全空きラインが 2 本以上」の局面は 302 / 9,555(3.2%)しかないので、
**交差する複数ラインの問題(前回指摘した証明の穴)だけが原因ではない** ——
全空きラインが 1 本しかない局面でも創出は成立する(§2.2 の出力例はいずれもそうだった)。

### 2.3 では 定理 4 はどう証明するのか

創出が現に起こる以上、**「創出は起きない」路線は死んだ**。生き残っているのは次の路線である。

> **路線: 創出は起きるが、R2 の判定を変えない。**

根拠は 2 つある。

**(a) 健全性(誤断定ゼロ)は既に証明済で、無傷である。**
`_turn57以下の証明.md` 系 D1 は「補題D + `G_3` より創出リーチは必ず段4 に生じる」と
「段4 のラベル追加は `m*` を変えない」の 2 点だけから従う。
創出が起きるかどうかには依存しない。**したがって `G_A2 ∧ G_T ∧ G_3` の下で R2 が勝敗を断定したとき、それは正しい。**

**(b) 厳密性(取りこぼしゼロ)には手数の勘定が要る。**
残る危険は「R2 が引き分けと言った局面で、白が**埋没した段4 の脅威**を創出して勝つ」場合だけである。
ここで効くのが手数である。全空きラインにリーチを作るには **攻撃側の 3 手**が要り(補題B)、
作った脅威を勝ちに変えるには**さらにツークツワンクを勝ち抜く**必要がある。
`_turn58以下の証明.md` 補題F(手数予算)と同じ勘定を、
**創出後の局面に R3 を適用して**行えばよい。具体的には:

> **補題 Z(予想)**: 白が全空き H4 ライン上に埋没した段4 リーチを創出したとき、
> 白はその過程で中立マスを 3 個消費している。R3 の縮約ゲームにおいて
> **偶数スタック(ρ = 0)を 1 本増やす代わりに中立マスを 3 個減らす**取引になり、
> 中立マスの偶奇が反転するので、**白は詰まる側になってしまう**。

この補題が示せれば「創出しても白は勝てない」= 厳密性が出る。
中立マス 3 個の消費は黒も 3 手使うので一見相殺されるが、
**創出に使う 3 マスはすべて段4 の自由マス**であり、
黒はその 3 手を自由に使えるという非対称性がある。ここを詰めるのが次の作業になる。

## 3. 定理 N の手証明(課題 2)

手で示せているのは次の 3 つである。

> **補題 N1(ゲートの毒の向きは色だけで決まる)**: 色 X の脅威を持つブロックのゲートは、
> 有効・無効によらず `opp(X)` にとって毒であり、X は素通り(burn)できる。
> **証明**: 補題 Q の 4 通りの組み合わせを書き下すだけ(§1.1 の確認)。∎

> **補題 N2(burn の効果)**: X がゲートを素通りすると `1 + r` マスが消費され、
> 手番は r が奇数なら X に戻り、偶数なら相手に移る。その上の中立マスが解放される。
> **証明**: 強制連鎖は 1 手ずつ交互に進むので、`1 + r` 手後の手番は `1+r` の偶奇で決まる。∎

> **補題 N3(押し返し)**: 中立マスが尽きた側が burn したとき、詰まる側が相手に移るのは
> **`(r が偶数) XOR (解放数が奇数)`** のときである。単一ラベル(r = 1)では
> **解放数 ρ = 4 − λ が奇数 ⟺ λ = 3** に一致する。
> **証明**: 補題 N2 の手番と、解放された中立マスを交互に消費した後の手番を合成する。∎

残っているのは次の 1 点である。

> **未証明**: **中立マス(自由マス)は個数の偶奇しか効かない。**
> `_turn57以下の証明.md` 定理 R (R1) の対戦略(自由マス 2 個を組にして応じる)がそのまま使えるはずだが、
> **ゲート手前のマス c_j は順序制約を持つので (R1) が直接は適用できない**(§1.2 の原因 b)。
> 「自由マス 2 個」については (R1) が使えるので、
> **c_j 側を別扱いする形に (R1) を書き直す**必要がある。

したがって現状の 定理 N′ は「補題 N1〜N3 + E ≤ 11 の完全列挙」という形で、
`_turn57以下の証明.md` の 定理 A と同じ強度(還元 + 有限検証)にはまだ達していない。

## 4. 定理 F′ の (ii) 側(課題 4)

`G_T0 ∧ G_bd ∧ G_C` で黒が勝てないことの証明は、補題 T1″(`_ゲート緩和の検討.md` §2.3)により
**「`G_C` の下で、数手かけて二重脅威を組めるか」**という一点に絞られている。

`theoremC1_check.cpp` の補助ゲームは、成功条件を
**「即置可能マスに 2 個以上のリーチを同時に作る」**に差し替えれば
そのまま二重脅威の判定に使える。次の作業として最も費用対効果が高い。

なお §2 の結果から予想されることとして、**二重脅威も「組めるが遅い」可能性が高い。**
その場合、定理 F′ も「起きるが結果を変えない」路線で示すことになる。
